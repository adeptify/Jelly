# Jelly 个人行动型编辑器优化规格

> 状态：待用户审阅
>
> 日期：2026-08-12
>
> 分支：`codex/jelly-editor-fluidity`
>
> 产品定位：本地优先的个人行动型文档；编辑体验对标滴答清单的轻量与流畅，不追求 Notion、飞书的重文档广度

## 1. 目标

Jelly 编辑器首先解决“最低成本把东西记下来”，其次才是把部分内容结构化、转成行动并安排进日历。

本轮成功不是增加更多 Block 类型，而是让用户在普通记录时感觉不到 Block 的存在：新建后不用找输入框，连续输入符合系统常识，结构和操作只在需要时出现，输入后即使立刻切换模块、退出或崩溃也不会丢内容。

目标体验可以概括为：

`进入笔记 → 直接写 → 需要时结构化 → 可选地变成行动 → 自动保存`

## 2. 产品边界

### 2.1 本轮必须做到

- 普通文字输入达到轻量原生编辑器的连续感。
- 空白文档只有一个输入位置和一个提示。
- 标题、正文、空白区域和键盘焦点形成无需解释的动线。
- Block 控件默认隐藏，悬停、聚焦、选择或输入 `/` 时才出现。
- Enter、Shift-Enter、Backspace、方向键、复制粘贴、撤销重做和中文输入法可靠。
- 保留现有有限 Block 类型，不扩张内容组件范围。
- 保留 Task Block 与日历、笔记与日历、灵感转笔记的现有闭环。
- 自动保存、草稿保护、异常恢复和 Markdown 导入导出继续可靠。

### 2.2 本轮明确不做

- Notion 式数据库、属性、公式、关系和多视图。
- 飞书式多人实时协作、评论、修订和权限系统。
- 表格、画板、投票、复杂媒体嵌入、多栏排版和页面发布。
- 滴答清单完整的提醒、习惯、番茄钟、优先级和任务管理体系。
- 模板市场、反向链接、知识图谱和 AI 写作。
- 云同步、移动端和跨设备冲突合并。
- 新增 Block 类型；本轮只改善已有能力的使用方式。

## 3. 优先级

| 层级 | 含义 | 功能点 |
|---|---|---|
| P0 | 编辑器是否合格；任一失败都不能验收 | F1–F5、F7、F8、F10、F12 |
| P1 | Jelly 的差异能力；不扩张，但必须保留且不妨碍写作 | F6、F9、F11 |
| P2 | 后续产品能力 | 本规格“明确不做”的全部项目 |

## 4. 逐功能优化方案与验收标准

### F1. 零摩擦新建与聚焦

**用户需求**

我新建一篇笔记后，可以马上开始记录，不需要先理解页面结构或寻找输入框。

**优化方案**

- 在笔记模块执行 `Command-N` 后立即创建笔记并聚焦标题。
- 标题按 Enter 后转入正文第一个可输入位置，不插入标题换行，也不触发额外保存按钮。
- 用户允许保留空标题；列表仍以“无标题”作为派生显示名，不把占位文字写进数据。
- 从灵感转为笔记时直接打开生成的准确笔记；若已有标题，正文成为首个编辑落点。

**验收标准**

- 在最终打包 App 中，`Command-2 → Command-N → 输入标题 → Enter → 输入正文` 全程无需鼠标。
- 新建完成到标题成为第一响应者之间不出现可感知等待或焦点跳动。
- 连续新建两篇空笔记不会被上一篇的无变化收尾阻塞。
- 新笔记不会继承上一条笔记的标题、正文、选择范围或撤销栈。

### F2. 单一空状态与整页可点击

**用户需求**

我看到的是一张空白纸，而不是多个等待填写的输入框。

**优化方案**

- 只有整篇文档没有可见内容时显示一次“开始写点什么…”。
- 当前空段显示光标；其他空段只保留正常空白行，不重复绘制提示。
- 正文下方空白区域属于编辑器：点击后聚焦最后一个可输入段；若文档以不可输入块结束，只创建一个尾随普通段。
- 空状态提示是视觉占位，不写入 `BlockDocument`、搜索索引或导出内容。

**验收标准**

- 任意时刻，编辑器可见的“开始写点什么…”不超过一个。
- 文档已有任意可见字符时，占位提示数量为零。
- 包含多个有意空段的文档仍保留段落节奏，但不会出现多份占位文字。
- 点击最后一段下方任意正文空白区域后直接出现可输入光标，不需要精确点中一行。
- 空状态和有内容状态切换不引起正文横向或纵向跳动。

### F3. 符合常识的连续输入

**用户需求**

我可以像使用普通文本编辑器一样输入、换段、合并和移动光标，不需要知道每段背后是一个 Block。

**优化方案**

- Enter 拆分当前段并进入下一段。
- Shift-Enter 只在当前段内插入软换行。
- 空普通段开头按 Backspace 合并到上一段；空特殊块先退回普通段，再按一次才合并。
- 左右方向键可跨段；上下方向键跨段时保留首次移动前的逻辑行字符列，目标行较短时夹到行尾，继续移动到更长行时恢复原列。
- 点击文字、空行和段落末尾都按系统文字编辑习惯定位光标。
- Block 之间不使用输入框边框、卡片背景或永久间距来暗示实现结构。

**验收标准**

- 段首、段中、段尾的 Enter 与 Backspace 结果均有表驱动自动化覆盖。
- Shift-Enter 后导出 Markdown 能保留块内换行语义。
- 在最终 App 连续输入至少 20 段中英文混排内容，光标没有跳回上一段或文档末尾。
- 从上一段末尾按右方向键、从下一段开头按左方向键，均只跨越一个段落边界。
- 删除最后一个可见字符后编辑器仍保留一个可输入位置。

### F4. 选择、剪贴板与撤销重做

**用户需求**

我可以自然选中跨段文字，复制、剪切、粘贴并反悔，不会因为跨了 Block 就失效。

**优化方案**

- 支持单段局部选择、跨段正向/反向选择和整块选择。
- 普通文本粘贴按换行结构生成段落；Jelly 自有富内容粘贴保留支持的 Block 和行内格式。
- Command-Z / Shift-Command-Z 只操作当前编辑会话，不误撤销日历或其他模块操作。
- 选区格式化、删除、剪切和链接操作必须是一笔原子撤销记录。

**验收标准**

- 跨三段正向和反向选择后复制，剪贴板文字顺序一致。
- 粘贴含空行、中文、英文、emoji 和列表前缀的文本后，字符与段落顺序完全一致。
- 一次多段粘贴只需一次 Command-Z 即可完整撤销，再一次重做可完整恢复。
- 编辑器有焦点但没有可撤销内容时，不允许命令落到 Workspace 撤销栈。
- 切换笔记后，上一条笔记的撤销记录不能修改当前笔记。

### F5. 中文输入法与输入性能

**用户需求**

我使用拼音输入时不丢字、不重字、不跳光标；长一点的笔记也不会越写越卡。

**优化方案**

- 输入法组合文字停留在原生文本系统中，候选未提交前不拆 Block、不触发 Markdown 转换、不写入主文档。
- 候选提交后只产生一次文档变更和一笔撤销记录。
- 将 Block 行视图的重建限制在内容、选择或状态真实变化的范围，避免每个按键重建整篇文档的视觉树。
- 大文档性能门禁使用固定数据集，区分 reducer、原生投影和完整 App 的实测结果。

**验收标准**

- 自动化覆盖拼音多次 marked-text 更新、候选提交、直接 unmark、取消组合、中文和 emoji。
- 最终 App 使用系统中文拼音连续输入至少 10 个包含选词过程的短句，无重复、缺失、乱码和光标跳动。
- 输入法候选状态下按 Enter、Backspace、方向键时由输入法优先处理，不提前改变 Block 结构。
- 500 个 Block、总计不少于 50,000 个字符的固定文档中，连续普通输入的 reducer + 原生投影耗时 p95 不高于 16ms；完整界面从按键到可见更新 p95 不高于 50ms，且不存在超过 100ms 的连续卡顿。
- 打开上述固定文档、滚动到中部并继续输入，字符不丢失，光标位置稳定。

### F6. 有限且渐进的结构化能力

**用户需求**

我平时只写文字；需要结构时，可以快速把当前段变成合适类型。

**优化方案**

- 本轮类型固定为：段落、一级标题、二级标题、三级标题、无序列表、有序列表、任务、引用、代码、分割线、链接。
- 保留已支持的 Markdown 行首转换和 `/` 菜单，不新增内容组件。
- `/` 菜单定位在当前光标附近，支持键盘上下选择、Enter 确认和 Escape 关闭。
- 未识别、非行首或正在输入法组合中的 `/` 与 Markdown 字符保持普通文本，不擅自转换。
- 特殊块按 Enter 后回到符合写作预期的段落或同类下一项，不让用户手动改类型。

**验收标准**

- 每一种支持类型都能通过 `/` 菜单创建，并能通过键盘完成选择。
- 已锁定的 Markdown 前缀继续通过现有 reducer 合同，未识别前缀逐字保留。
- `/` 菜单出现和消失时，已有正文位置不发生布局位移。
- 从特殊块退回普通段、拆分和合并后，Block ID、任务状态、代码信息和链接信息满足领域校验。
- 不出现“即将支持”的禁用类型、空菜单项或组件市场入口。

### F7. 渐进显示 Block 控件与重排反馈

**用户需求**

我写作时看不到工具噪音；想移动内容时，操作又容易发现。

**优化方案**

- 普通静止状态下拖拽柄视觉透明且不占用正文宽度变化。
- 段落悬停、键盘块选择或辅助功能聚焦时，才在正文外侧操作沟槽显示拖拽柄。
- 选中文字时，格式工具条以浮层出现，不插入文档布局。
- 拖拽过程显示明确插入线；释放后正文不闪烁、不丢焦点。
- VoiceOver 的重排动作放在对应段落的自定义动作中，不要求用户逐个听到永久的“移动 Block”按钮。

**验收标准**

- 打开有内容的笔记且鼠标未悬停时，屏幕上可见拖拽柄数量为零。
- 悬停当前段后只显示当前可操作范围的控件，移开后恢复安静状态。
- 控件显隐前后正文左边缘坐标不变。
- 选中文字后格式工具条出现，文档首段和当前段的纵向坐标不变。
- 拖动任意块时始终存在一个清晰落点；重启后顺序与放置结果一致。
- 鼠标、键盘和 VoiceOver 均可完成块重排，不把拖拽作为唯一途径。

### F8. 轻量、适合长期输入的视觉排版

**用户需求**

我能把注意力放在内容上，短记录不显得空，长内容也不累。

**优化方案**

- 编辑器是文档表面，不使用逐块边框或卡片背景。
- 正文内容宽度上限为 720pt；可用宽度不足时保留至少 28pt 左右安全边距。
- 普通正文建议使用 16–17pt 字号、1.45–1.6 倍视觉行高；中文和英文基线一致。
- 标题建议使用 30–34pt，分类、日历关系等元信息保持次要层级。
- 段间距用于表达文档节奏，不能把每段分割成独立表单。
- 颜色、背景、分隔线和选中态沿用日历已建立的暖色语义主题。

**验收标准**

- 浅色、深色模式下正文、占位、选区、链接、代码和引用均满足可读对比度。
- 360–500pt 窄编辑区、常规双栏窗口和全屏窗口均无文字裁切、横向滚动或控件重叠。
- 1 段、20 段和 500 Block 三种内容规模均完成视觉截图对比。
- 标题、元信息和正文一眼可区分，但页面中不存在第二个与标题竞争的强视觉中心。
- 空状态、悬停、选择、Slash 菜单、保存错误等关键状态均有截图证据。

### F9. 内容转行动但不打扰普通写作

**用户需求**

我可以把某一段变成要做的事并安排时间，但普通笔记不会自动变成任务系统。

**优化方案**

- 通过 `/任务` 或已支持的 Markdown 前缀显式创建 Task Block。
- Task Block 的完成勾选始终可辨认；安排日历、打开事项和解除关系在悬停、聚焦或上下文菜单中出现。
- Task Block 与 Calendar Item 保持一个用户可感知的完成状态，不复制两套状态。
- 普通段落不自动识别日期、不自动创建任务，也不弹出行动建议。

**验收标准**

- Task Block 可完成、重开、安排日历、打开准确日历事项和解除关联。
- 从编辑器和日历任一端切换完成状态，另一端立即投影同一完成时间。
- 解除关联后 Task Block 与日历事项按现有处置合同保留，不静默删除内容。
- Task Block 控件不会让所有普通段增加永久右侧按钮或额外高度。
- 非 Task Block 的日期文字和 `[]` 非前缀文本保持普通内容。

### F10. 安静但可信的自动保存与恢复

**用户需求**

我不想管理保存按钮，但需要确信内容不会丢；真有问题时，我能看懂发生了什么。

**优化方案**

- 正常自动保存保持安静，不持续显示“已保存”动画或状态噪音。
- 保存失败、冲突、只读和待恢复必须显示明确中文状态和下一步操作。
- 模块切换、选择其他笔记、归档、关闭窗口和退出应用都必须经过现有关闭保护屏障。
- 崩溃或强制退出后的未提交草稿进入恢复中心，由用户选择保留主文件、恢复当前笔记或另存为新笔记。

**验收标准**

- 输入后立即切换日历、选择其他笔记、关闭窗口和退出应用，重启后内容均存在。
- 模拟主文件保存失败时，草稿保护记录仍然存在，界面显示失败而不是假装成功。
- 模拟提交结果不确定、外部文件变化和旧版草稿时，恢复行为与现有 typed contract 一致。
- 正常写作期间不出现持续闪动的保存状态；异常发生后 1 秒内出现可理解的状态反馈。
- 恢复、另存和保留持久化版本均不产生重复 Note ID、重复 Task 关系或丢失正文。

### F11. 找回、整理与带走

**用户需求**

我以后能找到这篇笔记、做简单整理，也能把内容带到别处。

**优化方案**

- 保留最近、全部、归档三个互斥范围。
- 搜索覆盖标题和正文；分类继续复用工作空间共享分类。
- 保留 Markdown 导入导出，并在“更多”菜单中使用清晰中文名称。
- 本轮不增加文件夹、标签、页面树、反向链接或数据库。

**验收标准**

- 中文标题、英文正文、中文正文和 URL 均可命中搜索。
- 最近、全部和归档不会同时重复展示同一条笔记。
- 归档和恢复后，选择范围与条目位置符合当前生命周期。
- 支持类型经过 Markdown 导出再导入后，文字顺序、基础块类型和行内格式满足 codec 合同。
- 不支持的 Markdown 结构以明确诊断保留为正文，不静默丢弃。

### F12. 键盘与辅助功能完整可用

**用户需求**

我可以不依赖精确鼠标操作完成记录；使用辅助功能时也不会被实现细节淹没。

**优化方案**

- Tab 顺序为标题、必要元信息、正文；不会逐个进入隐藏的拖拽柄。
- 编辑器、段落类型、任务状态、链接和异常状态提供准确中文辅助功能描述。
- 块重排、格式化和任务动作具有键盘或 VoiceOver 自定义动作。
- 减少动态效果时，控件显隐不依赖位移动画表达状态。

**验收标准**

- 仅用键盘完成新建、标题、正文、多段输入、格式化、Task Block、撤销和模块切换。
- VoiceOver 连续阅读时先读内容，不在每段前重复朗读“移动 Block”。
- VoiceOver 可知道当前块类型、任务是否完成，并执行上移、下移等替代操作。
- 辅助功能树中隐藏控件不可点击、不可聚焦；显示后才进入对应交互状态。
- Reduce Motion 开启后所有必需状态仍清晰可辨。

## 5. 目标成熟度

Jelly 不需要在内容类型数量上追平 Notion 或飞书。目标成熟度如下：

| 能力 | 本轮目标 |
|---|---|
| 普通记录流畅度 | 达到或超过滴答清单桌面端轻量编辑体验 |
| 连续文档基本功 | 达到 Notion、飞书的基础写作常识，不追求高级文档能力 |
| 结构化内容 | 现有有限类型完整、安静、可靠 |
| 内容转行动 | 保持 Jelly 的 Task Block ↔ 日历直接闭环，优于普通文档待办 |
| 信息组织 | 搜索、分类、归档够用，不扩张知识管理系统 |
| 数据可靠性 | 单机本地优先场景必须强于依赖网络的编辑器 |
| 协作与同步 | 本轮为 0，不以占位入口冒充能力 |

## 6. 验收证据分层

### 6.1 自动化合同

- Block reducer：Enter、软换行、Backspace、移动、转换、粘贴、选择和格式。
- AppKit host：IME、第一响应者、跨 Block 选择、剪贴板、撤销和原生投影。
- SwiftUI presentation：空状态、控件显隐、布局稳定、Slash/格式浮层锚点和辅助功能。

## 7. Definition of Done

- F1–F12 的每一条验收标准都有 PASS、FAIL 或 UNVERIFIED 记录。
- 所有 P0 项必须 PASS；P1 项不得回归。真人专项若仍为 UNVERIFIED，不得声称“用户验收完成”。
- 全量自动化、release build、应用打包、失败路径、符号链接和严格签名门禁通过。
- 最终产物版本号、构建号、准确路径和 SHA-256 被记录。
- 保存修复前、空状态、短笔记、长笔记、Block 控件显隐、Task Block 和深浅色对比截图。
- 工作区干净，提交按交互呈现、输入行为、性能可靠性和验收证据拆分。
- 先推送专项分支；未经用户验收不合并 `main`。

## 8. 需要用户确认的设计决策

1. 普通记录优先级高于结构化能力；任何 Block 控件不得降低普通输入流畅度。
2. 编辑体验以滴答清单的轻量和即时为主要对标，Notion、飞书只作为连续文档基本功参考。
3. 本轮保留现有 Block 类型但不新增类型。
4. 多人协作、云同步、知识库和完整任务管理均不进入本轮。
5. 性能和中文输入法是发布门禁，不再只用“功能能跑”作为交付标准。
