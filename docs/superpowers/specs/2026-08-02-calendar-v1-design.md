# 个人月历 Calendar V1 设计规格

> 状态：产品方向已确认，等待书面规格复核
>
> 日期：2026-08-02
>
> 目标平台：macOS 桌面应用
>
> 当前阶段：设计，不代表已经实现或可用

## 1. 目标

Calendar V1 是一个本地优先、只提供月视图的个人彩色排期工具。它首先替代用户在滴答清单中实际依赖的付费月历能力：快速创建不同分类下的任务或日程，并为其设置可选的开始与结束时间。

第一版只证明一件事：用户可以不依赖清单系统，在一个安静、清晰、可靠的月历里完成个人排期与月度回顾。

成功意味着：

- 用户打开应用后直接看到当前月，不经过首页或清单。
- 用户可以在日期格内快速创建、分类和调整任务或日程。
- 任务可独立完成，普通日程没有完成状态。
- 每周固定星期几的重复事项行为可预测，单次例外不会污染整个系列。
- 应用离线、关闭和重启后数据仍完整，并能自行备份和恢复。

## 2. 已确认范围

### 2.1 平台

- 第一版只做 macOS 桌面应用。
- 不做移动端、网页版、Windows、账号体系或多设备同步。
- 数据结构保留稳定 ID、更新时间和重复系列关系，避免后续移动端与同步能力需要重建数据。

### 2.2 月视图

- 应用启动后直接进入当前月。
- 提供上月、下月和“今天”三个导航动作。
- 星期一为每周第一天。
- 明确标识今天和当前选中日期。
- 月格内同时呈现日期事项与定时事项。
- 当天内容超过可见容量时显示“还有 N 项”，打开当天抽屉查看完整内容。
- 月历顶部提供分类显隐筛选；筛选只改变当前视图，不修改事项本身。

### 2.3 任务与日程

所有内容共用“日历事项”模型，但有两种明确类型：

| 类型 | 完成状态 | 月历呈现 |
| --- | --- | --- |
| 日程 | 无 | 分类颜色、可选时间、标题 |
| 任务 | 有 | 完成框、分类颜色、可选时间、标题 |

规则：

- 任务完成后保留在原日期和原顺序中，以降低视觉权重的方式显示。
- 用户可以取消完成，恢复为未完成状态。
- 日程不出现完成框，也不能被标记完成。
- 每个任务或日程必须且只能属于一个分类。

### 2.4 时间

- 时间只有两种合法状态：“开始与结束都不设置”或“开始与结束都设置”，不允许只保存单边时间。
- 未设置时间的内容是“当天事项”，显示在该日期的定时事项之前。
- 用户开启“具体时间”时同时获得开始与结束时间输入；关闭时同时清除两者。
- 设置时间后，开始和结束时间必须在同一天；V1 不支持跨天事项。
- 结束时间不得早于或等于开始时间；不合法时在编辑器内直接提示并禁止保存。
- 拖动定时事项到其他日期时保留原开始时间、结束时间和时长。
- V1 不提供时区选择；内部仍应记录创建时的系统时区，避免未来同步后发生无声漂移。

### 2.5 每周重复

V1 只支持“每周固定星期几”：

- 可以选择一个或多个星期。
- 重复开始日期默认为事项日期。
- 如果开始日期不属于所选星期，首个实例是开始日期之后第一个符合星期规则的日期。
- 可以设置重复结束日期；结束日期按包含当天处理，不设置时持续重复。
- 结束日期不得早于开始日期；设置结束日期时，开始至结束区间内必须至少存在一个符合星期规则的实例，否则禁止保存并说明原因。
- 重复任务的每一次出现都有独立完成状态，完成本周不会影响下一周。
- 编辑、拖动或删除重复事项时，必须让用户选择“仅本次”或“本次及以后”；V1 不提供回写全部历史的“整个系列”。
- “仅本次修改”生成该次例外；“仅本次删除”只跳过该次。
- “本次及以后”以当前实例为分界拆分系列：分界前的实例、例外与完成记录保持不变；分界日及之后采用新的系列规则。

实例身份规则：

- 每个重复实例以“系列 ID + 原计划日期”获得稳定身份。
- 单次实例被拖到其他日期后，身份仍绑定原计划日期，避免再次生成一条原日期实例。
- 单次修改、跳过和完成记录都绑定该稳定身份。
- 拆分为“本次及以后”时，新系列从当前实例的原计划日期开始。
- 原系列中位于分界日及之后的单次例外迁移到新系列；即使新星期规则不再自然产生该日期，用户已经明确修改过的例外仍作为一次性实例保留。
- 迁移后的实例使用“新系列 ID + 原计划日期”作为身份；如果“本次及以后”来自整段拖动，则原计划日期、完成记录和例外一起按相同自然日差映射。
- “本次及以后”删除会删除分界日及之后的普通实例和例外，但保留分界日前的历史及完成记录。
- 撤销“本次及以后”的编辑、拖动或删除时，必须原子恢复原系列、拆分结果、例外和完成记录。

多星期拖动规则：

- 选择“仅本次”时，只移动当前实例并生成单次例外。
- 选择“本次及以后”时，以拖动的自然日差平移新系列的全部星期规则。例如周一实例拖到周二，原“周一、周三”从本次起变为“周二、周四”。
- 新系列的开始日期与可选结束日期按同一自然日差平移，未来单次例外也按同一自然日差平移；过去历史保持原日期。
- 周期按本地日历日计算，定时事项保持相同的本地墙上时钟时间，不使用固定的 `7 × 24` 小时换算。

V1 不支持每天、每月、每年、法定工作日、完成后重复或任意间隔。

## 3. 信息架构

V1 只有一个主窗口和一个独立管理窗口。

### 3.1 主窗口：月历

从上到下分为：

1. 顶部工具栏：月份标题、上月、下月、今天、分类筛选、分类管理入口。
2. 星期栏：周一至周日。
3. 月历网格：日期、事项、溢出入口。
4. 当天抽屉：只在用户点击日期数字或“还有 N 项”时出现，承接当天完整内容。

主窗口不设置清单侧栏、AI 入口、统计区或独立首页。

### 3.2 独立窗口：分类管理

分类管理不占用月历日常空间。它负责：

- 新建分类。
- 修改分类名称和颜色。
- 拖动调整分类顺序。
- 删除分类。
- 预览颜色在浅色和深色外观中的实际效果。

系统提供不可删除的“未分类”兜底分类，使用中性灰色。删除仍被事项引用的分类时，删除确认框要求用户在“迁移到另一分类”和“迁移到未分类”之间明确选择；未完成选择时不能继续删除。删除操作需要二次确认并支持撤销。

## 4. 核心交互

### 4.1 快速创建

1. 用户点击某个日期格的空白区域。
2. 日期格附近打开轻量创建浮层，标题输入框立即获得焦点。
3. 用户选择“任务”或“日程”。
4. 用户选择一个已有分类。
5. 用户按需开启具体时间并设置开始与结束时间。
6. 用户按需开启每周重复并选择星期。
7. 按 `Enter` 保存，按 `Esc` 放弃。

创建浮层不提供分类改名、改色或删除。分类选择器末尾可以进入分类管理窗口，但不会在浮层内嵌完整管理能力。

### 4.2 查看与编辑

- 单击事项打开详情浮层；同一浮层承担查看和编辑，避免跳转页面。
- 单击任务完成框只改变完成状态，不打开详情。
- 编辑普通事项时先保留在当前浮层草稿中；按保存按钮或 `Enter` 后才落盘，按 `Esc` 放弃未保存修改。
- 编辑重复事项前先选择“仅本次”或“本次及以后”，选择之后才应用变更。

### 4.3 拖动改期

- 用户可以把事项拖到另一个日期格。
- 普通事项立即改期，并显示可撤销提示。
- 重复事项拖动后先询问“仅本次”或“本次及以后”，并按第 2.5 节的实例身份与多星期平移规则处理。
- 拖动过程中显示目标日期，但不在 V1 中提供跨格拉伸或跨天长度调整。

### 4.4 当天抽屉

- 点击日期格右上角的日期数字，或点击“还有 N 项”，打开当天抽屉。
- 点击日期格空白区域始终进入快速创建；点击已有事项始终进入事项详情，三个热区互不重叠。
- 抽屉按“当天事项在前、定时事项按开始时间排序”的规则展示完整列表。
- 抽屉内支持完成任务、打开详情和创建新事项。
- 抽屉不会升级成日视图，不显示时间轴。

## 5. 分类与颜色规则

分类是任务或日程的唯一归属分类，不是可叠加的自由标签。

分类对象至少包含：

- 稳定 ID。
- 名称。
- 颜色值。
- 排序位置。
- 创建和更新时间。

颜色规则：

- 月历同时显示分类颜色与可读文字，不能只靠颜色传递信息。
- 默认提供一组克制、对比度合格的颜色。
- 允许自定义颜色，但需要在选择时校验文字与背景的可读性。
- 浅色和深色系统外观下都必须可识别。
- 同一分类在月历、筛选器、创建浮层和分类管理窗口中保持一致颜色。

## 6. 月格呈现规则

- 当天事项显示分类色标和标题，不显示伪造时间。
- 定时事项显示 `开始时间 + 标题`；完整起止时间在详情中可见。
- 任务在最左侧显示完成框；日程不保留空白完成框位置。
- 已完成任务降低对比度，但文字仍可阅读。
- 同一天内先按“当天事项 / 定时事项”分层，再按开始时间和创建顺序稳定排序。
- 月格空间不足时不压缩到不可阅读，而是保留前几项并显示“还有 N 项”。
- 分类筛选后重新计算“还有 N 项”，隐藏分类的事项不计入当前可见数量。

## 7. 本地数据与恢复

### 7.1 持久化原则

- 所有创建、编辑、移动、完成和删除操作均在本地事务性保存。
- 应用不依赖网络即可完成全部 V1 操作。
- 窗口关闭、应用退出或系统重启不会丢失已确认操作。
- 快速创建中尚未保存的输入不是已确认数据；用户取消、关闭浮层或应用异常退出时允许丢弃。

### 7.2 备份与恢复

- 用户可以手动导出一个带版本号的本应用备份文件。
- 备份包含分类、普通事项、重复规则、单次例外和任务完成记录。
- 恢复前先校验文件版本与结构；校验失败时不覆盖现有数据。
- 执行恢复前自动保留当前数据快照，并向用户明确说明恢复会改变什么。
- V1 的恢复只支持本应用备份，不承担滴答清单或其他日历格式导入。

## 8. 关键状态与恢复行为

| 状态 | 产品行为 |
| --- | --- |
| 空白月份 | 保持完整月历，不展示营销式空状态；提示点击日期开始创建。 |
| 日期内容拥挤 | 显示“还有 N 项”，由当天抽屉承接完整内容。 |
| 时间不合法 | 就地提示，禁止保存，不清空用户已输入内容。 |
| 删除普通事项 | 删除后出现撤销提示。 |
| 删除重复事项 | 必须选择仅本次或本次及以后，随后出现撤销提示。 |
| 删除正在使用的分类 | 要求迁移或转入未分类，不留下悬空引用。 |
| 备份文件无效 | 拒绝恢复并保留当前数据，说明失败原因。 |
| 应用异常退出 | 下次启动加载最后一次已确认状态；未保存草稿允许丢弃。 |

## 9. 快捷操作

V1 必须支持：

- `Enter`：保存当前创建或编辑。
- `Esc`：关闭浮层或取消当前未保存修改。
- `Command + Z`：撤销最近一次可逆的移动、完成或删除。

其他全局快捷键不作为 V1 验收要求，避免为了快捷键表增加隐藏复杂度。

## 10. 明确排除项

V1 不包含：

- 系统通知、提前提醒和稍后提醒。
- 日视图、周视图、年视图、列表视图或时间轴视图。
- 清单、文件夹、子任务、检查事项、优先级、附件和评论。
- 跨天事项。
- 每天、每月、每年、法定工作日、完成后重复或其他复杂重复。
- 外部日历订阅或同步。
- 滴答清单数据导入。
- 搜索、统计、协作和分享。
- 账号、云同步、多设备同步和移动端。
- 灵感、材料、知识库、AI 和 Chat。

以上项目只有经过新的产品确认才进入后续阶段，不能因为底层方便而提前暴露空入口。

## 11. V1 验收合同

交付不能只证明月历页面能打开。至少需要完成以下真实路径：

1. 创建“工作”“生活”等多个分类，设置不同颜色并调整顺序。
2. 在月历中创建一个无具体时间的任务和一个有起止时间的日程。
3. 完成任务并取消完成，验证日程没有完成状态。
4. 创建开始日期不属于所选星期的重复任务，验证首个实例落在之后第一个匹配日；设置结束日期，验证当天仍包含实例而次日不再产生。
5. 创建每周一、周三重复的任务，完成其中一次，验证下一次仍未完成。
6. 仅修改并移动一次重复事项，验证稳定实例身份阻止原日期重复生成，其他周期不变。
7. 从某次起修改重复系列，验证过去实例、例外与完成记录不变，未来实例采用新规则，未来单次例外按合同迁移。
8. 将周一、周三系列的某个周一实例拖到周二并选择“本次及以后”，验证未来变为周二、周四，过去保持不变；撤销后原子恢复全部系列、例外和完成记录。
9. 删除单次重复实例，再删除“本次及以后”，验证各自范围、历史保留和撤销行为。
10. 拖动普通事项改期，验证日期变化、时间保持和撤销。
11. 分别点击日期数字、日期格空白和已有事项，验证当天抽屉、快速创建和详情入口互不冲突。
12. 在同一天创建超过月格容量的事项，验证“还有 N 项”、分类筛选后的重新计数和当天抽屉。
13. 删除正在使用的分类，验证迁移、未分类兜底、无悬空事项，以及撤销后分类与全部引用原子恢复。
14. 验证时间只能“两者都空”或“两者都有”；输入不合法的起止时间时无法保存且输入不丢失。
15. 使用上月、下月和今天导航，验证月份、今天标识和选中日期正确。
16. 关闭并重启应用，验证分类、事项、重复例外和完成状态完整。
17. 导出备份，修改数据后恢复备份，验证恢复正确且失败不会覆盖现有数据。
18. 在浅色与深色系统外观下验证分类可读性和月格密度。

只有上述主路径、异常路径和恢复路径全部通过，Calendar V1 才能称为实现完成。连续真实使用后没有发生数据丢失、重复事项错位或明显操作阻塞，才能进一步称为个人可用。
