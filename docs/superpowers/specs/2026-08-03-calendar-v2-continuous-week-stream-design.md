# 个人月历 V2：连续周流与跨日事项设计规格

> 状态：已获用户直接实施授权；规格用于锁定实现合同
>
> 日期：2026-08-03
>
> 平台：macOS 桌面应用，本地优先
>
> 基线：Calendar V1；本规格只扩展月历，不引入清单、灵感或材料模块

## 1. 目标

本轮把现有“固定 42 格单月视图”升级为可长期使用的连续月历：以周为连续滚动单位，在全屏下优先展示约三周，使每天能够直接浏览 8–10 条事项，并让任务和日程成为真正可创建、移动、缩放、重复和撤销的跨日范围。

同时完成两项体验升级：

- 快速创建卡片跟随实际操作日期，而不是固定在窗口中央。
- 分类颜色扩展为五套色系，整体视觉采用已确认的 C「安静生活感」。

成功不只意味着界面出现新控件，还必须满足：旧数据无损升级、跨周条带身份稳定、重复实例修改语义明确、滚动扩展不跳位、失败不落半状态，并通过打包后真实应用验收。

## 2. 已确认产品语义

### 2.1 连续周流

- 日历始终是一条以星期一为起点的连续周流，不在小窗口切回“完整月份压进一屏”。
- 窗口多高就自然显示多少个完整或部分周行；全屏常用尺寸下约显示三周。
- 周行不因窗口缩小而被压扁；小窗口只减少同时可见周数。
- 上下滚动可无缝跨月、跨年，并提供轻微整周吸附。
- 顶部月份标题由视口中心周决定；横跨两个月的周以周四所在月份作为显示月份，避免标题在边界来回抖动。
- 左右箭头以当前焦点日期为基准加减一个自然月，并把目标日期所在周居中。
- “今天”把今天所在周居中。

### 2.2 跨日事项

- 待办和日程都支持开始日期与结束日期，首尾日期都包含。
- 单击空白日期格创建时，开始日与结束日默认都是当天。
- 从空白区域拖动可直接框选日期范围；支持正向、反向和跨出当前视口的拖选。
- 开启具体时间后，开始时间属于开始日，结束时间属于结束日，支持跨夜与跨多日。
- 同一事项在一周内显示为连续条带；跨周或跨月时按周分段，但所有分段保持同一身份和连续语义。
- 拖条带主体会整体移动且保持跨度；拖左端修改开始日；拖右端修改结束日；任何结果最少覆盖一天。
- 只有整个事项真实的最左端和最右端显示缩放柄，中间续接段不显示假边界。
- 跨日待办只有一个整体完成状态；勾选一次后，所有周段同步完成，不按天拆分。

### 2.3 每周重复

- V2 仍只支持“每周固定星期几”，不扩展每天、每月、每年等规则。
- 每个被勾选的星期都是独立实例起点，并使用同一个跨度模板；实例允许重叠。
- 例如跨度两天并勾选周三、周四，会分别生成周三至周四和周四至周五两个实例。
- 重复结束日期约束最后一次允许开始的日期；已经开始的实例完整保留其跨度。
- 重复实例移动或缩放仍询问“仅本次 / 本次及以后 / 取消”。
- “仅本次”保留稳定实例身份，只修改当前实例。
- “本次及以后”在当前实例边界拆分系列，历史保持不变；后续规则采用新的起点、星期或跨度。
- 取消不写入；确认后一次操作只产生一个领域命令和一条撤销记录。

## 3. 领域模型

### 3.1 统一时间范围

新增一等领域值 `CalendarSchedule`：

```swift
public struct CalendarSchedule: Codable, Equatable, Sendable {
    public var startDate: CalendarDate
    public var endDate: CalendarDate
    public var startTime: MinuteOfDay?
    public var endTime: MinuteOfDay?
}
```

不变量：

- `endDate >= startDate`。
- `startTime` 与 `endTime` 必须同时存在或同时为空。
- 同一天定时事项必须满足 `endTime > startTime`。
- 跨日定时事项按完整本地日期时间比较，因此允许 `23:00 → 次日 01:00`。
- 日期跨度按本地日历日计算，不使用固定秒数换算。
- `durationDays` 是包含首尾的派生值，不单独持久化到普通事项。

`CalendarItem.date` 与 `CalendarItem.timeRange` 由一个 `schedule` 替代。任务的完成状态仍属于整个 `CalendarItem` 身份。

### 3.2 重复系列模板

`WeeklySeries` 明确分离规则边界与实例跨度：

```swift
public struct WeeklySeries: Codable, Equatable, Sendable, Identifiable {
    public var id: UUID
    public var kind: ItemKind
    public var title: String
    public var categoryID: UUID
    public var ruleStartDate: CalendarDate
    public var recurrenceEndDate: CalendarDate?
    public var weekdays: Set<Weekday>
    public var durationDays: Int
    public var startTime: MinuteOfDay?
    public var endTime: MinuteOfDay?
    public var creationTimeZoneIdentifier: String
    public var createdAt: Date
    public var updatedAt: Date
}
```

规则：

- `durationDays >= 1`。
- 时间必须成对存在。
- 当 `durationDays == 1` 时必须满足 `endTime > startTime`；跨日时以日期跨度保证结束日期时间晚于开始。
- `recurrenceEndDate` 只表示最后允许开始的日期，不表示某次实例的结束日。
- `OccurrenceKey.originalDate` 始终表示实例原始开始日。移动、缩放、完成和拆分都不能让稳定身份丢失。
- `OccurrenceOverride` 可以覆盖显示开始日、`durationDays`、开始时间和结束时间，也可以表达跳过。
- 重复任务的完成状态仍按 `OccurrenceKey` 存储；每个跨日实例只有一个完成状态。

### 3.3 重复修改合同

- 拖主体：显示开始日整体平移，`durationDays` 与时间不变。
- 拖右端：开始日不变，只修改 `durationDays`。
- 拖左端：结束日固定，显示开始日变化，因此同时改变起点和 `durationDays`。
- “仅本次”修改 `OccurrenceOverride`，`OccurrenceKey` 不变。
- “本次及以后”沿用 V1 的系列拆分机制：旧系列截止到分界实例原始开始日前一天，新系列从该实例开始。
- 对主体平移或左端调整执行“本次及以后”时，新系列的规则起点、星期集合、未来例外、完成记录与可选重复截止日期按相同日差迁移，以保留剩余节奏。
- 右端缩放只修改后续实例跨度，不平移规则起点、星期或重复截止日期。
- 迁移后的未来例外和完成记录继续使用新系列 ID 与映射后的原始开始日。

## 4. 持久化与迁移

### 4.1 Schema V2

持久化版本提升为 2，并新增显式 V1 DTO。禁止通过“给新字段一个默认值”静默猜测旧数据。

V1 → V2 迁移：

- 普通事项 `date` → `schedule.startDate = schedule.endDate = date`。
- 普通事项 `timeRange` → 同日 `schedule.startTime/endTime`。
- 系列 `startDate` → `ruleStartDate`。
- 系列 `endDate` → `recurrenceEndDate`。
- 所有旧系列与旧例外的 `durationDays = 1`。
- 分类 ID、事项 ID、系列 ID、`OccurrenceKey`、完成状态、创建时间和更新时间原样保留。

解码行为：

- 同时支持 schema 1 和 schema 2。
- 未知 schema 在解析业务 payload 之前拒绝。
- 读取 V1 时只迁移到内存，不立即覆盖源文件；下一次正常保存或恢复成功后写出 V2。
- V1 备份可以恢复；恢复前的当前主文件继续原样保存为 rollback 快照。
- 任何迁移、校验或保存失败都不能覆盖最后一份有效主文件。

## 5. 投影与周条带布局

### 5.1 任意范围投影

固定 42 天的 `MonthProjection` 由 `TimelineProjection(dateRange:)` 替代。它输出保留完整身份与跨度的 `ProjectedEntry`，相交条件为：

```text
entry.endDate >= visibleStart && entry.startDate <= visibleEnd
```

重复查询必须回看至少 `durationDays - 1` 天，且必须额外纳入被例外修改为更长跨度的实例，确保“从视口前开始但延续进视口”的条带不会消失。

### 5.2 周段

每个 `ProjectedEntry` 在视图布局层按星期一至星期日切为 `WeekSegment`：

```swift
struct WeekSegment: Identifiable, Equatable {
    let id: WeekSegmentID
    let source: ProjectedEntryID
    let weekStart: CalendarDate
    let startColumn: Int
    let endColumn: Int
    let continuesBefore: Bool
    let continuesAfter: Bool
    let showsLeadingHandle: Bool
    let showsTrailingHandle: Bool
}
```

- 同一周内使用稳定的区间分道算法；一个跨日条带在整周只占一个 lane。
- 排序顺序：跨日事项、单日无时间事项、单日定时事项；同层按开始时间、创建时间和稳定 ID 排序。
- 当容量不足时，跨日条带必须整段显示或整段隐藏，不能只在部分日期消失。
- 被隐藏条带应在它覆盖的每个日期中正确计入“还有 N 项”。
- 分类筛选后重新投影和布局，隐藏分类不计入容量与 overflow。

## 6. 连续周流布局

- `WeekRow` 是 7 列背景、日期头、单日事项和跨日条带 overlay 的完整布局单元；不再让七个独立日期格各自绘制跨日事项。
- 周行使用固定的高密度目标高度，实际值通过真实 8–10 lane 视觉验收确定，初始实现目标为 252pt。
- 星期栏固定在顶部；周流在其下方纵向滚动。
- 默认持有当前周前后各 52 周的窗口；接近任一边缘时按 52 周扩展。
- prepend 前记录顶部可见周 ID 与像素偏移，插入后恢复同一锚点，视觉位置不得跳动。
- 视口中心最近的周是 `focusWeek`，顶部月份标题取该周周四。
- 轻微吸附只在滚动减速后把最近周边界拉齐，不拦截正常滚轮和触控板滚动。
- 自动扩展和月份标题变化不修改 Store，也不进入撤销栈。

## 7. 交互协调器

所有月历手势由一个 `CalendarInteractionCoordinator` 管理互斥状态：

```text
idle
selectingRange(anchorDate, currentDate)
movingItem(source, previewSchedule)
resizingLeading(source, previewSchedule)
resizingTrailing(source, previewSchedule)
pendingRecurrenceScope(command)
editing(draft, anchorDate)
```

命中优先级固定为：

1. 条带内部完成按钮和其他明确按钮。
2. 左右缩放柄。
3. 条带主体。
4. 日期格空白区域。

手势规则：

- 指针移动达到 7pt 才从按下进入拖动；未达到时保持点击语义。
- 空白区域拖动进入范围选择；事项主体进入移动；外端缩放柄进入对应缩放。
- 指针靠近视口顶部或底部时按周自动滚动；自动滚动节流，并通过统一日期格 frame map 计算当前指针日期。
- 拖动过程只更新 preview 和高亮，不写 Store。
- 普通事项松手后提交一个领域命令；重复事项先进入范围确认，确认后提交一个领域命令。
- 保存失败时回到原始条带位置并保留可读错误提示。
- 应用内跨周移动、缩放和范围选择使用统一手势系统；现有 `Transferable` 只作为兼容能力保留，不再承担核心月历交互。

## 8. 锚定创建与编辑

- 每个可见日期格通过 frame preference 上报窗口坐标。
- 创建/编辑卡片由月历根 overlay 放置，不再使用绑定在整个根视图上的固定 `.popover`。
- 单击创建时锚定被点击日期；范围拖选时锚定松手终点日期。
- 放置顺序优先右、左、下、上，并保留窗口安全边距；若空间不足，选择遮挡目标内容最少的位置。
- 卡片打开后继续显示完整范围高亮。
- 锚点日期因自动滚动暂时离屏时，卡片贴近对应窗口边缘，不关闭、不丢失草稿。
- 卡片提供开始日期、结束日期、可选开始时间与结束时间；单日事项仍保持紧凑布局。
- `Enter` 保存，`Esc` 放弃；无效范围就地提示且不清空输入。

## 9. 分类颜色与视觉系统

### 9.1 视觉方向

主方向为已确认的 C「安静生活感」：

- 浅色画布：燕麦米白，不使用冷白或大面积系统蓝。
- 深色画布：暖黑与深棕灰，不使用纯黑。
- 文字：暖黑/暖白；分隔线低对比但保持网格定位能力。
- 状态与分类色：陶土、鼠尾草、雾蓝、梅子等自然色，小面积使用。
- 日期格保持连续平面与柔和分区，不做厚重卡片墙或明显纸张拟物。
- 高密度、跨日连续性、今天、选中范围和拖拽反馈优先于装饰。

所有颜色、间距、圆角、阴影和动效通过语义 token 提供，禁止散落硬编码。

### 9.2 五套色系

分类管理提供五个色系，每组八个基础色，并保留自定义颜色：

| 色系 | 基础色 |
| --- | --- |
| 基础 | `4F7FFF` `735DD0` `D65772` `E58B39` `4EAC73` `2E9EB0` `9A7650` `8C8F96` |
| 马卡龙 | `8FB8F4` `A9A2E8` `D7A0C5` `F0A59A` `F4C58C` `E4D87D` `9ED8C0` `B9D69B` |
| 莫兰迪 | `8296A8` `B28F9B` `B6816D` `B6A184` `8F9878` `7F9B8B` `73959A` `8B7867` |
| 自然 | `4D83A6` `3E705A` `6F8652` `4D8D89` `C18A3D` `B86549` `81566F` `73716B` |
| 鲜亮 | `3D63E9` `7548D8` `D43282` `EF5E55` `F28A24` `83B928` `19A86B` `149DB4` |

- 选择色系只切换候选色，不修改草稿。
- 点击具体色点才更新分类预览。
- 分类仍只持久化基础 hex，保持现有数据兼容。
- `CategoryColorResolver` 从基础色生成 `accent / softBackground / outline` 三个浅色与深色角色。
- 浅色背景以燕麦画布混色，深色背景以暖黑画布混色；accent 必须相对所在表面达到 3:1，正文使用固定暖黑/暖白并达到 4.5:1。
- 自定义色使用同一解析算法；无法满足对比度时自动调节明度并在预览中展示最终颜色。
- 分类名称、条带文字与无障碍标签始终存在，颜色不是唯一信息来源。

## 10. 撤销、错误与恢复

- 创建、编辑、移动、缩放、完成、删除和分类变化仍通过 `CalendarStore` 的单一事务入口保存。
- 一次用户确认只注册一个整状态快照撤销；重复系列拆分、未来例外与完成记录迁移必须原子撤销。
- preview、滚动、筛选和月份标题变化不进入撤销栈。
- 保存失败时不保留半完成的领域状态；UI 回滚到原位置并显示可重试提示。
- 分类管理窗口与主窗口继续共享同一个 Store 和撤销命令。
- 打包、备份、恢复和损坏文件隔离沿用 V1 的事务性门禁，并增加 V1 → V2 迁移覆盖。

## 11. 无障碍与键盘

- VoiceOver 对跨日条带读取完整标题、类型、分类、开始与结束日期时间、完成状态，以及“从前一周继续/延续到下一周”。
- 同一事项的多个周段暴露稳定来源身份，避免读成多个互不相关事项。
- 缩放柄有“调整开始日期”“调整结束日期”标签和当前日期值。
- 不依赖拖拽才能完成操作；创建/编辑卡片始终可以修改起止日期。
- 保留 `Enter` 保存、`Esc` 取消、`Command-Z` 撤销。
- 减少动态效果时关闭强吸附动画和不必要位移，但不取消定位反馈。

## 12. 明确排除项

- 不新增清单视图、日视图、周视图、年视图或时间轴。
- 不新增提醒、通知、外部日历同步、账号、多端同步或协作。
- 不新增每天、每月、每年、工作日或任意间隔重复。
- 不实现灵感收集、材料摘要、知识库或 AI 功能；这些仍属于后续阶段。
- 不按天拆分跨日待办的完成状态。
- 不把跨日事项复制成多条独立单日数据。

## 13. 验收合同

### 13.1 领域与迁移

- 单日、跨夜、跨周、跨月、跨年范围校验正确。
- schema 1 主文件与备份迁移后，ID、分类、完成状态、例外、创建时间均不变。
- schema 2 round-trip 无差异；未知 schema 和损坏范围不覆盖当前主文件。

### 13.2 投影与布局

- 从视口前开始但延续进视口的普通事项、重复事项和加长例外都可见。
- 同周连续条带、跨周/跨月分段、续接样式和真实外端缩放柄正确。
- 容量不足时条带整段隐藏；每个被覆盖日期的“还有 N 项”准确。
- 分类筛选后的 lane 与 overflow 重新计算。

### 13.3 交互

- 正向、反向、跨视口拖选均得到正确范围；松手终点锚定，四边自动翻转，卡片打开后高亮保留。
- 主体拖动保持跨度；左右端缩放最少一天；取消不写入。
- 重复实例分别验证“仅本次”和“本次及以后”的主体移动、左缩放、右缩放、跨月、重复截止、未来例外与完成记录。
- 每次确认只有一条撤销；撤销后内存、磁盘和条带位置同时恢复。
- 保存失败时 preview 回滚，不产生半拆分系列。

### 13.4 连续滚动

- 手动连续滚动至少覆盖当前周前后各 52 周。
- 扩展周窗口时可见周与像素位置不跳动。
- 中心周月份标题、整月箭头和“今天”居中行为准确。
- 常见全屏尺寸下一屏约三周，每格直接显示 8–10 条；较小窗口保持周高而自然减少可见周数。

### 13.5 视觉、颜色与真实应用

- 浅色、深色、高密度日期格、跨日条带、新建卡片和分类管理均符合 C「安静生活感」。
- 五组共 40 个预设色及自定义色完成浅深模式可读性检查；颜色不是唯一识别信息。
