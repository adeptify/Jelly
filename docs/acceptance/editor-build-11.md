## 结论

Build 10 的验收结论已经撤回。Build 11 在重新修复、clean 全量回归、Release 性能门禁、重新打包和 Computer Use 真实操作后，通过本轮“轻量连续编辑器 + 灵光工作区”的内部产品验收。

本结论的准确含义是：在本轮明确覆盖的常用记录路径中，Jelly 已具备与滴答清单同一类的连续正文体验——新建后可直接写、正文只有一个焦点域、格式入口固定、选区不因工具栏丢失、长输入光标跟随、Tab 缩进有视觉反馈、切换模块不等待落盘。它不等于 Jelly 已复制滴答全部功能，也不把主观感受包装成无法证明的“逐帧完全相同”。

## 这轮真正修掉的问题

1. 连续编辑器曾用 Accessibility value 回写整篇纯文本，导致富文本被重新压平，选中词组点加粗时只剩首字符表现正确；现已移除这条错误回写路径。
2. 普通按键曾重投影、重排整篇文档；现在一字符编辑只替换对应 composed character，文档高度与 Task 位置在输入停顿后合并维护。
3. AppKit、Accessibility 和固定工具栏之间曾发生选区竞争；现在先接管真实 native range，操作后恢复完整选区和正文 first responder。
4. 左右/上下方向键曾通过 Block reducer 反复投影；现在交还原生文字系统处理，并只同步语义选区。
5. 选中文字后执行标题、列表或任务转换曾直接 no-op；现在会原子转换选区触及的全部行，并保留选区。
6. Tab 已经修改 `indentLevel`，但正文、圆点和复选框没有共同消费该层级；现在三者统一使用每级 20pt 的视觉偏移。
7. 长输入时第一次“显示光标”发生在延迟高度计算之前，导致数据已经写到第 45 行、视口仍停在顶部；现在高度更新后会再次把真实光标带入可见区。
8. 笔记切换到日历或灵光曾等待主文件保存；现在先提交输入法状态并立即启动草稿保护，磁盘保存继续在后台完成。
9. 灵光原来的捕获、搜索、分段、详情、元数据和动作堆在同一视觉层级；现在改成安静的快速捕获、明确列表选中态、单一详情阅读区和底部主次动作。

## Computer Use 真实 App 验收

验收对象不是 `.build` 中的开发可执行文件，而是每次修复后从 `dist/Jelly.app.zip` 重新解压出的 `Jelly.app`。数据目录使用独立的 `JELLY_ACCEPTANCE_DATA_DIRECTORY`，不会碰用户现有数据。

### 笔记和编辑器

- 从空数据进入笔记，空列表、空详情和新建按钮无图标重叠；单击新建后标题立即获得焦点，标题 Enter 进入正文。
- 连续输入多行，正文始终只有一个 `continuous-block-editor` 焦点域。
- 选中完整词组后加粗，整个词组生效；把光标移出加粗范围继续输入，新字符不会错误继承粗体。
- `Command-Z` 和 `Shift-Command-Z` 对同一字符的插入分别撤销和恢复。
- 选中整行后逐项使用 H1、无序列表、有序列表、任务、引用和行内代码，均就地生效；选区保留，焦点回到正文。
- Task Block 出现真实语义复选框，可完成后再次重开。
- 把连续两条列表中的第二条按 Tab 后，领域数据保存为 `indentLevel: 1`，最终重建 App 中正文和圆点都实际右移；Shift-Tab 可恢复。
- 输入 45 行后，视口从顶部自动滚到第 28–45 行，滚动条值为 `0.953488...`，最后一行光标真实可见。
- 正常 `Command-Q` 退出，再以同一数据目录启动最新包，标题、正文、标题/列表/任务/引用/代码结构、完成状态和缩进均恢复。

### 灵光

- 空工作区只有一个快速捕获入口、一个空列表提示和一个详情提示，没有旧版卡片与按钮挤成一团的问题。
- 回车捕获文字后，列表立即新增并自动选择，右侧只呈现内容、时间、分类和两个主次动作。
- 捕获 `https://example.com` 后真实得到 `Example Domain`、`example.com` 和“已获取”元数据状态。
- 搜索 `Build 11` 后只保留匹配行，右侧详情自动跟随可见选中项，不再显示已经被筛掉的旧详情。
- 归档后进入“归档”范围，按钮变为“恢复”；恢复后回到“待处理”。
- “转成笔记”会打开准确生成的笔记，标题与正文已经存在；返回灵光的“已成笔记”范围后，主动作变为“打开笔记”。
- 分类入口在详情右上角以“标签 + 当前分类”呈现，Accessibility Tree 可读为“灵光分类：未分类”，不会再出现含义不明的裸下拉框。

## 没有伪装成“已验收”的边界

- Computer Use 不能操作系统中文拼音候选窗。本轮真实界面确认中文标题、正文、灵光可写入与持久化；marked text、多次候选更新、提交、取消、Enter/Backspace 由 AppKit 集成测试覆盖。系统拼音候选窗仍需用户亲手验收。
- “永久删除”会产生不可恢复的数据删除。真实验收只打开到可见入口，没有在用户睡眠期间代替用户确认并执行；归档和恢复已经实操通过。
- 本轮没有重新手动走 Markdown 文件选择器、VoiceOver 听读、Developer ID 签名和 notarization；对应范围不能从本记录外推。
