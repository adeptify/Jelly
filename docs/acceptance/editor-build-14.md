## 本轮从真实操作中发现并修正的问题

1. 空列表的自定义光标比正文列左移 5pt。现在空项光标与上一条列表正文首字对齐，圆点保持在左侧。
2. “安排这个待办”曾按编辑器宽度拉伸；改为紧凑按钮后，又发现它跟在整篇文档末尾，长文中不可见。现在入口固定在底部格式栏右侧。
3. 首版固定入口只覆盖“打开时光标已经在待办”的测试；真实从正文移动到待办时不会出现。根因是父视图没有观察会话内选区变化；现在用观察会话的独立子视图更新，并增加从正文移动到待办的回归测试。
4. 分隔线按钮原来把光标留在不可编辑的分隔线上。现在一次点击会插入分隔线和其后的普通段落，光标直接落到可继续输入的位置，且一次 `Command-Z` 完整撤销。
5. 粗体、斜体和行内代码第二次点击时，按钮状态会熄灭，但文字格式没有移除。现在非空选区在格式操作后保持选中，第二次点击真正移除格式。
6. 已添加链接的文字再次点击“链接”会重复打开添加窗口。现在选区或折叠光标位于有效链接内时，再次点击直接移除链接。

## 输入全过程验收

本轮额外把验收粒度收紧到每一个中间状态，不能只看最后保存出来的正文是否正确。

| 操作序列 | 中间状态与结果 |
|---|---|
| 单击“新建笔记” | 页面立即切到新笔记，标题获得焦点，同时出现“已新建笔记 · 未分类”及撤销入口 |
| 标题逐键输入 `I`、`n`、`p`、`u`、`t` | 标题依次为 `I`、`In`、`Inp`、`Inpu`、`Input`，没有字符丢失或顺序错乱 |
| 标题按 Return | 标题不插入换行，正文立即成为 first responder，空正文光标出现在占位文字起点 |
| 正文逐键输入 `a`、`b`、`c` | 每次按键后字符立刻累积，光标逐字跟到末尾，没有回到行首 |
| 在折叠光标点击粗体后立刻输入 `x` | 第一个按键没有被工具栏吞掉，正文为 `abc` + 粗体 `x`，光标在 `x` 后 |
| 关闭粗体后立刻输入 `y` | `y` 立即写入且不继承粗体，正文为 `abc` + 粗体 `x` + 普通 `y` |
| 空段先输入 `-`，再输入空格 | `-` 阶段保持普通文字；输入空格后才转换成列表，空列表光标落在正文列 |
| 列表逐键输入 `one`，再按 Return | 字符逐步出现；Return 后新建空列表项，圆点与上一行节奏一致 |
| 空列表第一次 Backspace | 只退出为普通空段，不直接吞并前一项 |
| 再次 Backspace | 空段与上一条列表合并，光标落在 `one` 末尾 |
| 连续两次 Command-Z | 第一次恢复普通空段，第二次恢复空列表项；每一步都可见且可理解 |
| 列表输入 `two`，左移两次后输入 `X` | 结果为 `tXwo`，说明方向键后的实际插入位置没有跳到行首或文档末尾 |
| 选择 `tXwo` 后点击斜体 | 选区保持高亮，整段文字生效，正文重新获得焦点 |
| 在仍选中的斜体文字上输入 `q` | 选区被替换为斜体 `q`，没有残留旧文字或丢失当前格式 |

补充宿主门禁：真实鼠标激活格式按钮后，不等待下一轮 RunLoop 就立即发送第一个按键；断言字符写入、格式正确、光标前进且正文仍为 first responder。

Computer Use 每次状态抓取含工具自身等待，因此上述操作只能证明中间状态正确，不能拿工具总耗时证明真实响应速度。真实按键到可见更新仍由编辑器性能测试单独记录，主观“是否跟手”仍需用户判断。

## 真人中文输入法脚本

以下过程必须在本 Build 14 上由用户本人使用系统拼音输入法执行，当前保持 `UNVERIFIED`：

1. 连续输入一段至少 100 字中文，过程中多次翻候选页、改选第二/第三候选，不按段落停顿。
2. 候选窗口打开时按左右方向键、Backspace、Esc 和 Return，确认命令只作用于候选或组词，不误触列表、换行或删除前文。
3. 中文与英文、数字、全角标点、emoji 连续混输，确认光标始终紧跟正在组合的文字。
4. 在普通段落、标题、无序列表、待办和引用中分别完成一次候选提交与取消。
5. 组合文字尚未提交时点击格式栏、切换模块再返回，确认不会产生重复字符、丢字或旧候选覆盖新正文。
6. 连续输入 10 分钟后完成跨段选择、复制粘贴、Undo/Redo、退出重开，并主观判断光标动画、按键反馈和滚动是否跟手。

## 没有冒充真人验收的部分

- Computer Use 无法可靠操作系统中文拼音候选窗。AppKit marked-text、候选更新、提交、取消、emoji 有自动化覆盖，但这只能算工程证据。
- 光标高度、位置和可见性有截图与宿主测试；“看起来是否自然”“连续输入是否顺手”仍需用户本人判断。
- 富文本实操使用的是现有测试数据；验收完成后，用户另行明确授权永久清空全部测试笔记与灵感。数据清理不计入富文本验收结果。
- 当前产物仍是 ad-hoc 签名，不代表公开发布就绪。
