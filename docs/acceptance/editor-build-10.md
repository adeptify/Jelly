## 结论

本轮基础编辑器、笔记和灵感的核心动线已经通过真实 App 操作验收。最终发行候选为 `0.3.0 (10)`。

## 真实 App 验收

验收使用从 `dist/Jelly.app.zip` 解压出的原样 App，并通过独立的 `JELLY_ACCEPTANCE_DATA_DIRECTORY` 从空数据启动。操作通过 macOS Computer Use 完成。

通过的用户动线：

1. 新建笔记后，标题自动获得焦点；标题回车或点击正文可以立即开始写。
2. 连续输入多段正文；选中同一段中的词组后执行剪切、粘贴、撤销、重做，词组仍留在原行，不会被拆成新段落。
3. 编辑完成后直接新建下一篇笔记，不出现保存阻塞；从日历返回并重开关联 Task Block 后立即新建，也会真正切到空白新笔记。
4. 用正文内容搜索笔记；归档笔记、进入归档区、恢复笔记。
5. 把正文转为 Task Block，安排到日历；从日历完成后回到笔记立即显示已完成；从笔记重开后，日历同步为未完成。
6. Task Block 首尾有空格时仍可安排到日历；日历标题只去掉首尾空格，笔记原文不被改写。
7. 捕获文字灵感、搜索、归档、恢复、转成笔记；转换后自动回到笔记“最近”列表，并选中刚转换的笔记。
8. 捕获 `https://example.com` 链接灵感，真实获取到 `Example Domain` 标题和 `example.com` 域名元数据。
9. 创建“产品验收”分类并分配给笔记；分类值持久化显示。
10. `⌘Q` 正常退出，使用同一数据目录重启后，笔记标题和正文仍在，并可继续编辑。

真实验收中发现并修复的回归：

- 已落盘且内容相同的自动保存被错误当成“不安全”，导致用户不能新建下一篇笔记。
- 同一段内局部剪切粘贴被误当成结构化 Block 粘贴，文字被拆成新段落。
- 从日历完成关联任务后，笔记编辑器显示旧的未完成状态。
- Task Block 首尾空格与 Calendar Item 自动清理空格的规则不一致，导致“安排失败”。
- 重开关联 Task Block 后新建笔记只写入数据，却没有切换编辑器。
- 从灵感转成笔记时，如果笔记列表之前停在“归档”，右侧打开新笔记但左侧仍显示“归档为空”。

## 尚未用真人方式覆盖的项目

- Computer Use 无法模拟真实中文拼音输入法的候选词过程；本轮只确认中文标题、分类和灵感可以通过原生控件写入并持久化。中文 IME 的组合输入、提交和撤销由 AppKit 界面测试覆盖，但仍建议用户验收时亲手输入一段中文。
- 本轮检查了完整的 Accessibility Tree，关键按钮、编辑区、Task Block 和路由均有可读名称；没有另行开启 VoiceOver 做真人听读验收。
- Markdown 导入/导出由自动化测试覆盖，本轮没有在系统文件选择器中手工完成一次导入和导出。
