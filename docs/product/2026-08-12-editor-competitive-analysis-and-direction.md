# Jelly 编辑器竞品分析与方向决策

> 日期：2026-08-12
>
> 状态：已结合滴答清单桌面端真人操作复核，等待用户确认取舍
>
> 分析对象：Notion、飞书文档、滴答清单 `8.0.75 (472)`、Jelly `0.2.1 (3)`

## 1. 分析目的

这份文档回答三个问题：

1. 用户需要编辑器解决什么问题？
2. Notion、飞书、滴答清单和 Jelly 分别把这些问题解决到了什么程度？
3. Jelly 应该借鉴什么、拒绝什么，最终做到什么程度？

竞品能力以 2026-08-12 可访问的官方产品与帮助文档为证据，不把功能宣传等同于真人实测。滴答清单的基础编辑动线另外使用本机 macOS 桌面端 `8.0.75 (472)` 完成 Computer Use 实测。Jelly 结论来自远端 `main@2182d3a` 的代码、自动化记录和实际使用截图。

评分含义：

- `4`：成熟，用户基本不需要理解实现机制。
- `3`：完整可用，但有明确边界。
- `2`：能力存在，体验或覆盖不完整。
- `1`：技术上能做，用户体验不合格。
- `0`：没有。

## 2. 用户需求到核心功能的映射

| 用户需求 | 核心功能 |
|---|---|
| 打开以后马上能写 | 新建、自动聚焦、标题进入正文、单一空状态、点击空白继续写 |
| 像普通文字一样连续输入 | Enter、Shift-Enter、Backspace、方向键、跨段选择、复制粘贴、撤销重做、中文输入法 |
| 需要结构时才出现结构 | 标题、列表、任务、引用、代码、链接、分割线、Markdown、斜杠菜单、选择工具条 |
| 可以重新组织内容 | 多段选择、拖拽排序、缩进、合并拆分、落点反馈 |
| 写下来的内容可以变成行动 | 待办、日期、提醒、日历安排、完成状态同步 |
| 以后还能找到并继续使用 | 搜索、分类、标签、目录、页面关系、归档、模板 |
| 内容不会丢，也可以带走 | 自动保存、离线、崩溃恢复、版本历史、导入导出 |
| 需要时能和别人一起工作 | 分享、权限、评论、协同编辑、修订记录 |

前四项决定编辑器是否合格；后四项决定编辑器属于哪种产品。

## 4. 产品功能视角比较

| 产品能力 | Notion | 飞书 | 滴答清单 | Jelly 当前 |
|---|---|---|---|---|
| 编辑器表面 | 成熟的通用块文档 | 成熟的协作块文档 | 标题 + 单一连续正文 + 底部固定格式栏 | 不合格，数据结构直接暴露给用户 |
| 输入内核 | 跨块编辑、移动、转换成熟 | 协同输入、格式和离线同步成熟 | 常见富文本、Markdown、列表与任务输入成熟 | 内核约 3，呈现约 1，能力与体验严重断层 |
| 内容类型 | 非常丰富，包含数据库、媒体、嵌入 | 非常丰富，包含任务、表格、媒体、画板 | 标题、列表、附件、子任务等常用类型 | 已有段落、三级标题、列表、任务、引用、代码、分割线和链接 |
| 行动系统 | 数据库任务和 Notion Calendar | 文档任务与任务中心双向同步 | 产品核心，任务和日历最强 | Task Block 与 Jelly 日历直接关联，方向正确 |
| 信息组织 | 页面树、数据库、链接、搜索 | 云空间、知识库、全文搜索 | 清单、标签、智能筛选 | 分类、搜索、归档，单层结构 |
| 数据可靠性 | 云端、离线下载、版本和导出 | 云端实时保存、断网同步、修订和导出 | 多端同步 | 本地 Journal、冲突和恢复合同很深，用户感知较弱 |
| 协作基础 | 完整 | 完整且与组织通讯打通 | 轻协作 | 无 |
| 可迁移性 | Markdown、HTML、CSV、PDF 等 | Markdown 导出保留常见结构 | 不是公开产品重点 | 已有 Markdown 导入导出，入口较深 |

## 5. 四个产品的真实侧重点

### 5.1 Notion：结构化内容

Notion 的优势是几乎任何内容都能成为可组合 Block，并继续进入页面层级、数据库和多种视图。它适合搭建文档系统和知识工作流，但这种广度也带来理解和配置成本。

Jelly 应借鉴：

- 连续文档表面。
- Block 控件按需出现。
- 跨 Block 选择、移动和转换符合文字编辑常识。

Jelly 不应借鉴：

- 数据库、属性、公式、视图和庞大的 Block 目录。
- 把简单记录逐步变成搭建系统的工作。

### 5.2 飞书：协作文档

飞书的优势不是某一个编辑按钮，而是文档、评论、消息、任务、人员和权限处于同一组织环境。它适合团队共创、评审和执行。

Jelly 应借鉴：

- 文字与 Block 融合的连续感。
- 自动保存默认安静，失败状态明确。
- 文档内 Task 与外部行动对象保持一个状态的表达方式。

Jelly 不应借鉴：

- 多人光标、评论、修订、权限和组织通讯。
- 表格、画板、投票和复杂媒体组件。

### 5.3 滴答清单：轻量记录与行动

滴答清单不追求成为最强长文工具。它让标题、正文、Markdown、任务、日历和提醒保持短路径，编辑器服务于记录和执行，而不是让用户建设一套文档系统。

本轮桌面端实测确认了以下行为：

- `Command-N` 直接打开当前清单的快速记录框，先记下一句话的成本很低。
- 笔记详情是独立标题加一块连续正文；标题按 Enter 会把焦点交给正文。
- 正文中的普通 Enter、列表自动延续、空行退出列表、选择、撤销和重做都留在同一编辑面内。
- Markdown 行首输入可直接得到标题和列表；原始内容仍能从可访问性树读成 Markdown 文本。
- 主要格式入口固定在编辑区底部，不随着每个段落常驻，也不会在选中文字后突然贴着选区弹出浮动工具条。
- 在 `8.0.75 (472)` 的笔记正文实测中，输入 `/` 只得到普通字符；因此 Slash 菜单不是本轮对标滴答的依据。
- Note 仍可拥有日期、子任务、清单和标签等行动属性，但这些属性没有把正文切成一排独立输入框。
- 多个底部图标按钮在 macOS Accessibility Tree 中只有“按钮”而没有可理解名称；视觉用户能识别，VoiceOver、自动化和 Agent 难以可靠识别。这一点不能照抄。

自动化输入中文在 Electron 应用中存在漏字，无法作为中文输入法质量判断；中文候选、长时间输入手感仍需真人专项验收。

Jelly 应主要对标：

- 打开即写和极少的界面噪音。
- 单一连续正文、Markdown 快捷输入和固定格式栏。
- 内容、任务和日历之间的短路径。
- 不要求用户理解复杂文档模型。

Jelly 不应复制：

- 提醒、优先级、习惯、番茄钟和完整任务管理体系。
- 让笔记成为任务详情的附庸。

### 5.4 Jelly：个人行动型文档

Jelly 已经具备一个可形成差异的位置：

- 灵感负责最低成本捕获。
- 笔记负责长期内容。
- Task Block 把部分内容变成行动。
- 日历决定何时执行。
- 本地优先和恢复机制保护内容。

当前主要矛盾不是功能少，而是基础编辑体验没有把已有能力托起来。用户看到的是 Block 数据结构，而不是一篇可以自然书写的文档。

### 5.5 本轮实测带来的决策修正

原方案把“悬停拖拽柄、Block 菜单、选区浮动工具条”放在很高优先级，主要参考了 Notion、飞书的块文档交互。但滴答真实使用呈现的是另一条更符合 Jelly 当前定位的路径：

`连续正文 → Markdown / 固定格式栏 → 只有行动内容才显出特殊身份`

因此本轮采用以下原则：

> 数据层 Block 化，交互层连续文本化。

判断过程是：

1. Jelly 保留 Block 数据模型，便于 Task Block、导入导出、关系和恢复继续工作。
2. 底层存在 Block，不代表普通段落必须表现成独立对象。
3. 拖拽柄和 Block 菜单会不断提醒用户“你在操作 Block”，与最低成本记录的目标冲突。
4. 选区浮动工具条也不是当前必需；以后 Jelly 的选区还要承载“与 AI 讨论、解释、改写、生成任务”等差异能力，应该到那时统一设计。
5. 所以普通段落拖拽、Block 菜单和选区浮动格式栏从本轮 P0 后置，不为保留旧实现而牺牲连续输入。

这不是永久删除 Block 能力。Task Block 的勾选、安排日历等身份仍应在需要时显现；将来若真实场景证明段落重排或 AI 选区交互有价值，再单独设计并验收。

## 6. 已确认的优化方向

### 6.1 定位

Jelly 是“本地优先的个人行动型文档”。

- 编辑体验主要对标滴答清单的轻量、即时和低成本。
- 连续书写基本功参考 Notion、飞书，但不追求重文档能力。
- Jelly 的差异不是更多 Block，而是灵感、笔记、Task Block 和日历的本地闭环。

### 6.2 必做

- 新建后直接写，标题 Enter 进入正文。
- 单一空状态和整页可点击。
- 正文在用户感知上是一个连续编辑面，连续输入、中文输入法、粘贴和撤销可靠。
- Markdown 快捷输入与底部固定格式栏提供有限结构，不让格式入口追着选区或段落跳动。
- Task Block 只在成为行动时显出身份，普通段落不显示拖拽柄或 Block 菜单。
- 轻量长文排版和大文档性能门禁。
- 保留 Task Block ↔ 日历、笔记 ↔ 日历、灵感 → 笔记。
- 保留搜索、分类、归档、自动保存、恢复和 Markdown 导入导出。
- 所有图标按钮拥有准确的辅助功能名称、状态和动作，视觉与机器语义一致。

### 6.3 不做

- 数据库、知识图谱、反向链接和高级页面结构。
- 多人协作、评论、修订和权限。
- 完整任务管理、提醒、习惯和专注系统。
- 新 Block 类型、复杂媒体和页面搭建能力。
- AI、云同步和移动端。
- 普通段落拖拽柄、Block 菜单和选区浮动格式工具条。

### 6.4 做到什么程度

| 维度 | 目标 |
|---|---|
| 记录成本 | 不使用鼠标即可完成新建、标题和正文输入 |
| 普通输入 | 用户感觉在一个连续编辑面里写作，而不是操作 Block |
| 结构能力 | 现有类型够用，Markdown 和固定工具栏优先，Block 身份按需出现 |
| 行动闭环 | Task Block 到日历的距离短于通用文档产品 |
| 可靠性 | 单机写作、退出、崩溃和恢复必须可信 |
| 功能广度 | 有意低于 Notion、飞书和完整任务管理工具 |
| 可理解性 | 人看得懂、VoiceOver 读得懂、Agent 也能通过可访问性树准确操作 |
