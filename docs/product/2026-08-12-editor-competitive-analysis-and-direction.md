# Jelly 编辑器竞品分析与方向决策

> 日期：2026-08-12
>
> 状态：方向已口头确认，等待本文档复核
>
> 分析对象：Notion、飞书文档、滴答清单、Jelly `0.2.1 (3)`

## 1. 分析目的

这份文档回答三个问题：

1. 用户需要编辑器解决什么问题？
2. Notion、飞书、滴答清单和 Jelly 分别把这些问题解决到了什么程度？
3. Jelly 应该借鉴什么、拒绝什么，最终做到什么程度？

竞品能力以 2026-08-12 可访问的官方产品与帮助文档为证据，不把功能宣传等同于本轮真人实测。Jelly 结论来自远端 `main@2182d3a` 的代码、自动化记录和实际使用截图。

评分含义：

- `4`：成熟，用户基本不需要理解实现机制。
- `3`：完整可用，但有明确边界。
- `2`：能力存在，体验或覆盖不完整。
- `1`：技术上能做，用户体验不合格。
- `0`：没有。

## 2. 用户需求到核心功能的映射

| 用户需求 | 核心功能 |
|---|---|
| 打开以后马上能写 | 新建、自动聚焦、标题进入正文、单一空状态、点击空白继续写 |
| 像普通文字一样连续输入 | Enter、Shift-Enter、Backspace、方向键、跨段选择、复制粘贴、撤销重做、中文输入法 |
| 需要结构时才出现结构 | 标题、列表、任务、引用、代码、链接、分割线、Markdown、斜杠菜单、选择工具条 |
| 可以重新组织内容 | 多段选择、拖拽排序、缩进、合并拆分、落点反馈 |
| 写下来的内容可以变成行动 | 待办、日期、提醒、日历安排、完成状态同步 |
| 以后还能找到并继续使用 | 搜索、分类、标签、目录、页面关系、归档、模板 |
| 内容不会丢，也可以带走 | 自动保存、离线、崩溃恢复、版本历史、导入导出 |
| 需要时能和别人一起工作 | 分享、权限、评论、协同编辑、修订记录 |

前四项决定编辑器是否合格；后四项决定编辑器属于哪种产品。

## 3. 用户视角比较

| 用户需求 | Notion | 飞书 | 滴答清单 | Jelly 当前 |
|---|---|---|---|---|
| 打开就写 | **4**：页面首先是普通文档，Block 操作在悬停或 `/` 后出现 | **4**：连续文档，格式和块操作按需出现 | **3**：笔记和任务详情都能直接写，入口服从任务系统 | **2**：能新建和输入，但标题到正文不自然，空 Block 重复暴露 |
| 连续书写 | **4**：支持跨 Block 选文、Markdown 和常规文字行为 | **4**：软换行、快捷键和 Markdown 成熟 | **3**：常规富文本够用，不以长文为核心 | **1**：底层能输入，界面却像一排独立表单 |
| 结构按需出现 | **4**：悬停显示 `+` 和拖拽柄，`/` 选块，选中文字显示工具条 | **4**：多种内容块默认融入连续文档 | **3**：标题、列表、附件、子任务和 `/` 足够克制 | **1**：块类型存在，但实现机制一直露在外面 |
| 重组内容 | **4**：整块、多块和跨段文字均可选择、移动和转换 | **4**：可移动单块，也能折叠标题后移动章节 | **2**：任务列表重排强，文档内部重组不是核心 | **2**：拖拽和多块选择存在，但缺少安静状态和清晰反馈 |
| 文字变行动 | **3**：待办、日期提醒和任务数据库完整，但复杂任务需要数据库建模 | **4**：文档任务可同步任务中心 | **4**：任务、提醒和日历是产品核心 | **2**：Task Block 与日历合同很好，但编辑体验阻碍使用 |
| 找到与复用 | **4**：页面层级、数据库、链接、搜索、模板成熟 | **4**：云空间、知识库、全文搜索和文档链接成熟 | **3**：清单、标签、筛选、模板和搜索实用 | **2**：分类、正文搜索、最近、全部、归档已存在，仍是单层结构 |
| 不丢与带走 | **4**：云备份、版本、离线页面和多种导出 | **4**：实时云保存、断网同步、版本与 Markdown 导出 | **4**：多端同步是基础能力，版本恢复不是公开重点 | **3**：单机草稿保护和恢复较强，缺少多端同步和版本历史体验 |
| 多人协作 | **4**：评论、提及、建议、权限和共同编辑 | **4**：文档、消息、任务和权限在同一组织环境 | **2**：共享清单和任务分配，不是协作文档 | **0**：本地个人应用 |

## 4. 产品功能视角比较

| 产品能力 | Notion | 飞书 | 滴答清单 | Jelly 当前 |
|---|---|---|---|---|
| 编辑器表面 | 成熟的通用块文档 | 成熟的协作块文档 | 任务优先的轻量富文本 | 不合格，数据结构直接暴露给用户 |
| 输入内核 | 跨块编辑、移动、转换成熟 | 协同输入、格式和离线同步成熟 | 常见富文本和任务输入成熟 | 内核约 3，呈现约 1，能力与体验严重断层 |
| 内容类型 | 非常丰富，包含数据库、媒体、嵌入 | 非常丰富，包含任务、表格、媒体、画板 | 标题、列表、附件、子任务等常用类型 | 已有段落、三级标题、列表、任务、引用、代码、分割线和链接 |
| 行动系统 | 数据库任务和 Notion Calendar | 文档任务与任务中心双向同步 | 产品核心，任务和日历最强 | Task Block 与 Jelly 日历直接关联，方向正确 |
| 信息组织 | 页面树、数据库、链接、搜索 | 云空间、知识库、全文搜索 | 清单、标签、智能筛选 | 分类、搜索、归档，单层结构 |
| 数据可靠性 | 云端、离线下载、版本和导出 | 云端实时保存、断网同步、修订和导出 | 多端同步 | 本地 Journal、冲突和恢复合同很深，用户感知较弱 |
| 协作基础 | 完整 | 完整且与组织通讯打通 | 轻协作 | 无 |
| 可迁移性 | Markdown、HTML、CSV、PDF 等 | Markdown 导出保留常见结构 | 不是公开产品重点 | 已有 Markdown 导入导出，入口较深 |

## 5. 四个产品的真实侧重点

### 5.1 Notion：结构化内容

Notion 的优势是几乎任何内容都能成为可组合 Block，并继续进入页面层级、数据库和多种视图。它适合搭建文档系统和知识工作流，但这种广度也带来理解和配置成本。

Jelly 应借鉴：

- 连续文档表面。
- Block 控件按需出现。
- 跨 Block 选择、移动和转换符合文字编辑常识。

Jelly 不应借鉴：

- 数据库、属性、公式、视图和庞大的 Block 目录。
- 把简单记录逐步变成搭建系统的工作。

### 5.2 飞书：协作文档

飞书的优势不是某一个编辑按钮，而是文档、评论、消息、任务、人员和权限处于同一组织环境。它适合团队共创、评审和执行。

Jelly 应借鉴：

- 文字与 Block 融合的连续感。
- 自动保存默认安静，失败状态明确。
- 文档内 Task 与外部行动对象保持一个状态的表达方式。

Jelly 不应借鉴：

- 多人光标、评论、修订、权限和组织通讯。
- 表格、画板、投票和复杂媒体组件。

### 5.3 滴答清单：轻量记录与行动

滴答清单不追求成为最强长文工具。它让标题、正文、Markdown、任务、日历和提醒保持短路径，编辑器服务于记录和执行，而不是让用户建设一套文档系统。

Jelly 应主要对标：

- 打开即写和极少的界面噪音。
- 轻量富文本与 `/` 命令。
- 内容、任务和日历之间的短路径。
- 不要求用户理解复杂文档模型。

Jelly 不应复制：

- 提醒、优先级、习惯、番茄钟和完整任务管理体系。
- 让笔记成为任务详情的附庸。

### 5.4 Jelly：个人行动型文档

Jelly 已经具备一个可形成差异的位置：

- 灵感负责最低成本捕获。
- 笔记负责长期内容。
- Task Block 把部分内容变成行动。
- 日历决定何时执行。
- 本地优先和恢复机制保护内容。

当前主要矛盾不是功能少，而是基础编辑体验没有把已有能力托起来。用户看到的是 Block 数据结构，而不是一篇可以自然书写的文档。

## 6. 已确认的优化方向

### 6.1 定位

Jelly 是“本地优先的个人行动型文档”。

- 编辑体验主要对标滴答清单的轻量、即时和低成本。
- 连续书写基本功参考 Notion、飞书，但不追求重文档能力。
- Jelly 的差异不是更多 Block，而是灵感、笔记、Task Block 和日历的本地闭环。

### 6.2 必做

- 新建后直接写，标题 Enter 进入正文。
- 单一空状态和整页可点击。
- 连续输入、中文输入法、粘贴和撤销可靠。
- Block 控件、Slash 菜单和格式工具条渐进出现且不扰动布局。
- 轻量长文排版和大文档性能门禁。
- 保留 Task Block ↔ 日历、笔记 ↔ 日历、灵感 → 笔记。
- 保留搜索、分类、归档、自动保存、恢复和 Markdown 导入导出。

### 6.3 不做

- 数据库、知识图谱、反向链接和高级页面结构。
- 多人协作、评论、修订和权限。
- 完整任务管理、提醒、习惯和专注系统。
- 新 Block 类型、复杂媒体和页面搭建能力。
- AI、云同步和移动端。

### 6.4 做到什么程度

| 维度 | 目标 |
|---|---|
| 记录成本 | 不使用鼠标即可完成新建、标题和正文输入 |
| 普通输入 | 用户感觉在编辑一篇连续文档，而不是操作 Block |
| 结构能力 | 现有类型够用、按需出现、键盘优先 |
| 行动闭环 | Task Block 到日历的距离短于通用文档产品 |
| 可靠性 | 单机写作、退出、崩溃和恢复必须可信 |
| 功能广度 | 有意低于 Notion、飞书和完整任务管理工具 |
