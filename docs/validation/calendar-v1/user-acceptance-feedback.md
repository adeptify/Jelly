# 个人月历用户验收反馈

验收开始：2026-08-03

说明：本文件记录真实试用反馈。用户已于 2026-08-03 确认本批反馈收集结束并授权统一优化；实现合同见 `docs/superpowers/specs/2026-08-03-calendar-v2-continuous-week-stream-design.md`。

## #1 新建事项卡片应跟随目标日期格

- 状态：待统一优化
- 触发路径：在月历日期格中创建事项。
- 当前表现：新建事项详情卡片固定出现在窗口中的统一位置，与刚刚点击的日期格缺少空间关联。
- 期望表现：卡片跟随本次创建所点击的日期格，优先显示在该日期格附近，让用户能直观看出“正在为哪一天创建”。
- 自适应要求：靠近窗口边缘时自动选择左侧、右侧、上方或下方的可用空间；不得超出窗口，也尽量不要遮住目标日期和该日期已有事项。
- 连续操作：改点其他日期重新创建时，卡片锚点随新的目标日期格更新。
- 截图证据：`user-feedback/01-quick-create-anchor.png`（778×598）。

## #2 全屏月历每屏展示三周，提高单日事项容量

- 状态：待统一优化
- 使用规模：单日通常可能出现 8–10 条待办。
- 当前问题：全屏仍一次展示完整月份的 5–6 周，单个日期格高度有限，事项较多时很快折叠为“还有 N 项”，不便直接浏览当天安排。
- 期望表现：全屏模式下一屏展示 3 个周行，而不是把整个月的所有周行同时压缩在一屏；以更高的日期格换取更大的单日事项展示容量。
- 容量目标：在常见全屏尺寸下，单个日期格优先直接展示约 8–10 条紧凑待办，再根据实际可用高度决定是否出现“还有 N 项”。
- 月份完整浏览：已确认采用连续纵向滚动，以整周为基本滚动单元并做轻微吸附；全屏视口约显示三周，不采用“三周一页”的硬翻页。
- 跨月边界：已确认周流可以无缝跨月份；视口中心周进入新月份后，顶部月份标题自动更新。左右箭头仍按整月跳转，“今天”回到包含今天的周并将其置于视口中部。
- 响应式边界：已确认始终采用连续周流，不在小窗口切回“完整月份压进一屏”。窗口多高就自然展示多少周；全屏/大窗口重点保证约 3 周和单日 8–10 条容量，小窗口则减少同时可见的周数，不能强行塞入 3 周导致内容溢出。

## #3 支持跨多天的待办与日程

- 状态：待统一优化
- 当前问题：创建卡片目前只有单个日期，同一事项无法直接表达跨越多个自然日的持续范围。
- 能力目标：待办和日程都能设置开始日期与结束日期，并在月历中作为一个连续的跨日事项呈现。

### 入口 A：在月历空白区域拖选日期范围

- 用户从某个日期格的空白区域按住并拖动到另一个日期格，例如从 6 号拖到 7 号。
- 拖动过程中实时高亮即将创建的连续日期范围；松手后打开新建卡片，并预填开始日期为 6 号、结束日期为 7 号。
- 创建卡片的锚点已确认：单击创建时贴近被点击的日期格；跨日拖选时贴近鼠标松手所在的终点日期格。靠近窗口边缘时自动翻到可用方向，且卡片打开后继续保留整段日期范围高亮。
- 新建卡片中仍可选择“待办”或“日程”，也可以继续修正起止日期后再保存。
- 手势必须与已有事项的拖动改期区分：从日期格空白区域开始是“框选范围并新建”，从已有事项开始是“移动已有事项”。

### 入口 B：在新建卡片中编辑起止范围

- 用户仍可单击某一天打开新建卡片。
- 卡片不再只有一个“日期”，而是允许设置开始日期与结束日期；默认二者都是点击的当天。
- 开启“具体时间”后，开始时间和结束时间分别从属于开始日与结束日，因此可以表达跨夜或跨多天的定时日程；不开启时则表达按自然日覆盖的跨日事项。
- 结束日期不得早于开始日期；同一天仍保持当前单日事项体验，不额外增加操作负担。
- 已确认跨日范围可与“每周重复”组合：例如周三至周四的两日事项开启每周重复后，每周生成相同两日跨度；重复结束日期约束最后一次允许开始的实例，已经开始的实例仍完整保留其跨度。
- 当每周重复同时勾选多个星期时，每个勾选日都作为一个独立实例起点，并使用相同跨度；允许实例互相重叠。例如两日跨度同时勾选周三、周四，会分别生成周三至周四和周四至周五两个实例。

### 月历呈现与边界

- 同一周内优先显示为跨越对应日期格的连续条带，而不是每天复制一条互不相关的事项。
- 跨周或跨月时按周行分段绘制，但各段需保留明确的延续关系与统一身份。
- 日期范围按首尾日期均包含处理，例如 6 号至 7 号表示覆盖两天。
- 跨日待办只有一个整体完成状态，不按覆盖日期拆成每日完成；在任意可交互位置勾选后，所有跨周、跨月分段都同步显示为完成。
- 已确认支持条带两端拖拽缩放：拖左端修改开始日，拖右端修改结束日；拖条带主体则整体移动且保持跨度。
- 缩放过程中实时高亮新的日期覆盖范围并显示起止日期；任何结果都必须至少覆盖一天，左右端不得互相越过。
- 跨周分段条带只有整个事项最左侧的起点段显示左缩放柄、最右侧的终点段显示右缩放柄，中间续接段不能被误当作新的边界。
- 重复跨日事项缩放沿用范围确认：选择“仅本次”时只改变当前实例的跨度；选择“本次及以后”时从当前实例开始改变后续每次的跨度，过去实例保持不变；取消不写入。每次确认后的缩放只注册一条原子撤销记录。
- 后续方案需补齐跨日事项的移动、调整起止边界、完成、删除、重复规则及撤销语义，避免只支持创建而无法继续管理。

## #4 分类颜色扩充为多套色系

- 状态：待统一优化，已完成第一轮资料检索
- 当前问题：分类管理目前只有 8 个离散预设色，选择空间偏少，颜色之间没有明确的风格分组。
- 期望表现：预设颜色按“色系”组织；用户先选择色系，再从该色系的一组颜色中选择分类色，同时继续保留系统自定义颜色入口。

### 建议的首批色系

1. **基础**：延续当前清晰、平衡的蓝、紫、红、橙、绿、青、棕、灰。
2. **马卡龙**：柔和的天空蓝、蓝莓、薰衣草、玫瑰、蜜桃、柠檬、薄荷、开心果等低饱和浅色。
3. **莫兰迪**：灰蓝、藕粉、陶土、燕麦、橄榄、鼠尾草、灰青、棕褐等低饱和灰调色。
4. **自然**：海洋、松林、苔藓、湖水、琥珀、赤陶、梅子、岩石等自然意象色。
5. **鲜亮**：靛蓝、紫罗兰、洋红、珊瑚、橙、青柠、祖母绿、亮青等高识别度颜色。

### 交互与质量要求

- 在当前色点区域上方增加紧凑的色系切换，例如“基础 / 马卡龙 / 莫兰迪 / 自然 / 鲜亮”；每套先控制在约 8 个颜色，避免一次展示几十个无层级色点。
- 选择色系只切换候选色板，不应立即修改分类；点击具体颜色后才更新预览。
- 色系名称和颜色名称使用易懂中文，不展示难记的内部 token。
- 颜色必须同时生成或选定浅色、深色模式适配值，不能把同一个浅色机械照搬到深色背景。
- 马卡龙等浅色不能仅依赖低对比背景表达分类；需要配套更深的色条、描边或文字策略，继续满足当前浅/深预览和可读性门禁。
- 候选色之间还要有足够的感知差异，并补做常见色觉缺陷模拟，避免多个分类只能靠非常接近的红绿细微差别区分。
- 自定义颜色继续保留，并沿用当前十六进制输入、实时预览和对比度检查。
- 截图证据：`user-feedback/04-category-color-families.png`（1802×1104）。

### 检索参考

- Radix Colors：每个颜色提供 12 阶色阶，并分别提供浅色、深色及透明变体，适合作为技术实现和可读性映射参考。
- Material 色彩系统：从基础色生成 tonal palette，并通过明暗变体承担不同 UI 角色，适合作为一套色系内部的层级生成参考。
- Pastel/Color Hunt 等灵感库：用于搜集马卡龙、柔和粉彩等审美方向；最终颜色仍需经过本产品自己的浅深模式和对比度验收，不能直接照搬图片色板。

## #5 整体视觉需要更个性化、更温暖

- 状态：主方向已确认
- 方向决定：选择 C“安静生活感”作为主视觉。采用燕麦底色、自然色谱、柔和分区与暖黑深色；后续可以吸收其他方案的局部，但不能削弱 C 的安静、自然和生活感。
- 当前感受：现有界面完成了清晰、可用的基础，但整体仍接近常见系统日历或通用效率软件，辨识度和个人气质不足。
- 目标感受：更温暖、更有陪伴感和个人空间感；打开它应像进入自己的工作台或手账，而不是又一个标准 SaaS 日历。
- 设计边界：个性化不能牺牲月历扫读效率、每天 8–10 条事项的高密度、跨日条带、拖拽反馈、文字对比度和原生桌面操作感。

### 建议先比较的三个方向

1. **日光手账**：米白纸张、暖灰线条、墨色文字、柔和分类色；克制加入纸感或印刷感细节，但不做拟物化笔记本。
2. **个人工作室**：更有编辑设计感的字体层级、日期数字和留白，使用分类色签、标签页或标记笔式的小面积识别元素，整体温暖但利落。
3. **安静生活感**：从木色、燕麦、陶土、鼠尾草、雾蓝等自然色出发，弱化冷蓝系统感；深色模式采用暖黑、深棕灰和低亮度自然色，而不是纯黑加高亮蓝。

### 探索与决策方式

- 在修改生产界面前，先基于同一份真实月历数据做 3 张可比较的高保真视觉方案，保持布局与信息量一致，只比较视觉语言。
- 每个方向同时给出浅色、深色和高密度日期格片段，不能只做一张空状态概念图。
- 对比内容至少包含：顶部导航、三周全屏密度、8–10 条事项日期格、跨日事项、今日/选中日、分类筛选、新建卡片和分类颜色。
- 用户选择一个主方向后，再吸收另外两案中明确喜欢的局部，不在实现阶段把三个方向混成一套没有主次的风格。
- 保留 macOS 窗口、键盘和菜单行为；视觉可以有性格，但操作仍应直接、安静、稳定。
